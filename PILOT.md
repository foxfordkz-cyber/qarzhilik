# QARZHЫ Academy — рабочий пилот

Сайт и Flutter-приложение используют одну базу аккаунтов, доступов и результатов. Это версия для проверки сценария обучения и демонстрации проекта. Публикация в интернете и магазинах приложений не выполнялась.

## Что реализовано

- `/academy` — новый кабинет ученика на русском и казахском: программа, прогресс, уроки, задания и тесты.
- `/start` — регистрация, вход и возвращение к выбранному уроку.
- Первый урок открыт для ознакомления; остальные доступны после решения преподавателя. Закрытие проверяется на сервере, а не только кнопками интерфейса.
- Ученик отправляет заявку. Преподаватель на `/teacher` видит заявки и число пройденных уроков, выдаёт доступ на 30/365 дней или отзывает его. Действия записываются в журнал базы.
- Ответы Academy проверяются на сервере. Порог прохождения — 75%, лучший результат сохраняется; более слабая повторная попытка не стирает завершение урока.
- Flutter: вкладки «Курс», «Прогресс», «Профиль», регистрация/вход, заявки, уроки, тесты и видеоплеер с сохранением позиции. Один исходный проект для Android, iOS и веб-демонстрации.
- Настроен сервер Node.js + SQLite, который можно размещать на VPS без Cloudflare. Существующий Worker также сохранён.
- Подготовлено подключение приватного S3: преподаватель связывает урок с MP4, сервер проверяет доступ и выдаёт временную ссылку. Без настроенного хранилища интерфейс показывает «Видео готовится».

Программа содержит 15 уроков, адаптированных из существующей открытой библиотеки. Это черновик для утверждения преподавателем, а не утверждённая программа MOOC. 15 × 30 минут — план видеокурса; настоящие видео ещё не добавлены. Старые публичные материалы и тесты библиотеки остаются открытыми; они не подходят для защищённой аттестации.

## Быстро показать на компьютере

Нужен Node.js 24. Выполнить из корня проекта в PowerShell:

```powershell
npm install
$env:PORT = '8790'
npm run dev:local
```

Открыть:

- Сайт: http://localhost:8790/
- Курс: http://localhost:8790/academy?lang=ru
- Преподаватель: http://localhost:8790/teacher?lang=ru
- Flutter в браузере после сборки: http://localhost:8790/app/

Сервер слушает только компьютер (`127.0.0.1`). Эти адреса не являются публичной ссылкой для комиссии. Миграции применяются автоматически. Данные сохраняются в `.local/qarzhy.sqlite`; повторный запуск их не удаляет. Не публиковать эту базу или `.env` в Git.

### Назначить преподавателя

Сначала зарегистрировать его аккаунт на локальном сайте. В другом терминале:

```powershell
node server/admin.mjs teacher@example.kz
```

Заменить адрес на реально зарегистрированный. CLI меняет только локальную выбранную базу; при другом `DB_PATH` использовать одинаковое значение у сервера и команды. Через обычную регистрацию преподавательские права получить нельзя. Для удалённой D1 это отдельное административное действие, данная команда её не меняет.

### Сценарий демонстрации на 5–7 минут

1. Показать главную страницу и переход в Academy. Переключить русский/казахский.
2. Зарегистрировать ученика, открыть первый урок, пройти тест. На главной курса проверить прогресс.
3. Открыть закрытый урок и отправить заявку.
4. В другом браузерном профиле войти преподавателем, открыть `/teacher` и выдать доступ.
5. Обновить страницу ученика: остальные уроки открыты, виден срок доступа.
6. В Flutter войти тем же учеником и показать сохранённый результат. В веб-версии Flutter того же браузера сессия сайта подхватывается автоматически.
7. Пояснить: видео подключаются после подготовки; оплата и коммерческий запуск — следующий этап. Не представлять тестовые аккаунты или результаты как реальную статистику апробации.

## Flutter: запуск и сборка

В проекте используется Flutter 3.41.2 / Dart 3.11. Для команд ниже Flutter должен быть в PATH. На этом компьютере SDK находится в `C:\Users\karab\Downloads\flutter_windows_3.41.2-stable\flutter\bin\flutter.bat`.

```powershell
cd mobile
flutter pub get
flutter analyze
flutter test
flutter build web --base-href /app/
flutter build apk --debug
```

Веб-сборку из `mobile/build/web` Node-сервер отдаёт по `/app/`, API берётся с того же домена. После пересборки обновить вкладку. Эта демонстрация показывает Flutter-интерфейс, но не заменяет тесты на телефонах.

Debug Android по умолчанию обращается к `http://10.0.2.2:8790` — адресу компьютера из Android Emulator. HTTP разрешён только debug-манифестом. Для телефона по USB можно использовать:

```powershell
adb reverse tcp:8790 tcp:8790
flutter run --dart-define=API_BASE_URL=http://127.0.0.1:8790
```

На физическом телефоне без проброса портов стандартный debug APK к локальному серверу не подключится. Не использовать URL действующего старого сайта, пока на нём нет новых миграций и Academy API.

Для внешней установки сначала нужен опубликованный HTTPS API. Пример параметра будущей сборки:

```powershell
flutter build appbundle --release --dart-define=API_BASE_URL=https://YOUR-DOMAIN.kz
```

`YOUR-DOMAIN.kz` — шаблон, его заменить своим адресом. Перед Play Store настроить собственный ключ подписи вместо шаблонной debug-подписи Android, заменить стандартные иконки и проверить реальные устройства. iOS собирается на Mac с Xcode, сертификатами и аккаунтом разработчика; на этом Windows-компьютере iOS-сборка не проверена. Native release без HTTPS адреса API намеренно не подключается.

## Хранилище видео

1. Создать приватный S3 bucket у выбранного провайдера. Для требования Казахстана письменно подтвердить место хранения, резервных копий и условия договора; код не подтверждает соответствие требованиям ЕНУ или программы финансирования.
2. Загрузить свои MP4 с корректным `Content-Type: video/mp4`; провайдер должен поддерживать HTTP Range. Подготовить файлы для быстрого начала воспроизведения (MP4 faststart).
3. В окружении сервера задать `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_REGION`. Endpoint — HTTPS origin без пути bucket. Аккаунту приложения дать только чтение нужных объектов; загрузку выполнять отдельным аккаунтом провайдера.
4. Для Flutter Web настроить CORS bucket только на свой сайт: GET/HEAD, Range; expose Content-Length, Content-Range, Accept-Ranges. Не открывать публичный доступ ко всему bucket.
5. В `/teacher` привязать ключ, например `course/lesson-01.mp4`, к выбранному уроку.
6. Проверить настоящее воспроизведение, перемотку, продолжение, отсутствие доступа у гостя/отозванного ученика и стоимость исходящего трафика.

Сейчас реализован MP4 с подписанными ссылками сроком 1 час. Уже выданная ссылка действует до истечения срока даже после отзыва доступа. Это не DRM; запись экрана не блокируется. Реальное подключение S3 ещё не проверено, потому что endpoint и ключи не предоставлены. Для массового видеопросмотра потребуются адаптивное качество HLS/CDN и отдельный нагрузочный тест. 1 500 одновременных зрителей не проверялись; текущая SQLite-версия рассчитана на пилот, её масштабирование нужно обосновать измерениями.

## Перенос на VPS

Пример окружения есть в `.env.example`. Node не читает `.env` автоматически: запускать `node --env-file=.env server/index.mjs` или передавать переменные через менеджер процессов.

- Linux VPS с Node.js 24, постоянным диском для базы и отдельным системным пользователем.
- Скопировать исходники, `public`, `migrations`, при необходимости `mobile/build/web`; установить зависимости.
- Настроить `NODE_ENV=production`, `APP_ORIGIN=https://ваш-домен`, `DB_PATH` вне каталога обновляемого кода. Не терять базу при новой версии.
- Nginx/Caddy завершает HTTPS и проксирует на `127.0.0.1:8790`. Для Nginx передавать `Host`, `X-Forwarded-Proto`, а `X-Real-IP` **перезаписывать** значением `$remote_addr`. Только после этого включать `TRUST_PROXY_LOOPBACK=1`; без него ограничение входа считает IP самого прокси.
- Настроить автозапуск, ротацию логов, мониторинг и резервные копии SQLite через штатный online backup. Проверить восстановление. Не копировать только основной файл во время записи WAL.
- Сначала развернуть отдельный стенд и выполнить сценарий демонстрации; затем назначить настоящего преподавателя. Перенос пользователей старой D1 не реализован — локальная база отдельная.

Срок сессии — 30 дней; сайт использует HttpOnly cookie, native Flutter — bearer token в системном защищённом хранилище. Есть проверка Origin для запросов браузера и ограничение попыток входа по IP/email. На боевом домене нужен HTTPS.

## Что нужно перед продажей курса

1. Утвердить программу, авторские права и настоящие видеозаписи; добавить субтитры и проверить учебные задания.
2. Определить продавца, оферту, правила возврата, согласия и политику обработки данных; подтвердить требования к размещению и апробации.
3. Выбрать эквайринг и подключить оплату с серверной проверкой подписанных webhook, идемпотентностью, возвратами и выдачей доступа только после подтверждённого платежа. Текущая заявка не является оплатой.
4. Добавить подтверждение email, восстановление пароля, удаление аккаунта, рабочую поддержку, управление сессиями. Данные механизмы пока отсутствуют.
5. Подготовить отдельные новые материалы/тесты, если требуется контроль знаний: нынешние упражнения взяты из публичной библиотеки, ответы доступны в её старых JSON. Серверная проверка защищает запись результата от подделки, но не превращает такой тест в независимую аттестацию.
6. Провести тесты на Android/iOS, аудит доступа, нагрузочный тест и проверку восстановления. У преподавателя пока выводятся последние 500 заявок без пагинации.
7. Проверить актуальные требования магазинов к цифровым курсам, оплате, аккаунтам и публикации; настроить подписи и оформить страницы приложения.

## Проверки

```powershell
npm test
cd mobile
flutter analyze
flutter test
```

Серверные тесты используют отдельную временную базу: общий вход web/mobile, запрет самостоятельного получения роли преподавателя, заявки, выдача/отзыв/истечение доступа, проверка теста, сохранение лучшего результата, выход, защита от чужого Origin, лимиты входа и подпись URL S3. Flutter-тесты проверяют API-ошибки и пользовательский путь от программы к регистрации на маленьком экране. Реальные платежи, S3 и нагрузка в эти проверки не входят.
